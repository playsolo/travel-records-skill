# Beta invitation / 内测招募文案

## 中文社群长帖

**你还记得去年住过哪些酒店吗？我在做一个从邮件整理旅行记录的小工具。**

订房确认、改期、取消和最终账单经常散在邮箱里。回顾旅行时，要重新找日期、分辨重复订单，还得核对最后到底付了多少。

我做了 Travel Records，希望把这些资料整理成可核对的清单：住宿、航班、餐饮预订，以及日期、状态、金额和依据。预订和实际发生分开记录，读不到或有冲突的地方保留待复核项。

现在是桌面私有内测，想先邀请 10–20 位经常旅行或出差的朋友。先用一段你记得的行程测试，看看能否顺利安装、拿到可打开的清单，以及是否有漏项或错误。普通核对不需要安装 FotoNest。

[查看项目与当前安装条件](https://github.com/playsolo/travel-records-skill/blob/main/README_ZH.md)。项目自带合成样例，可以先看结果再决定是否连接邮箱。

如果愿意参加，请在本帖回复你的电脑系统、使用的桌面客户端，以及最想整理哪类记录。我会先确认环境和内测安装方式。公开回复请不要附邮箱地址、邮件截图、账单或订单号；连接邮箱需要你自己授权。

当前真实验证以有限酒店材料为主，航班、餐饮仍需更多案例；网页、手机及无人值守连续执行尚未验收。很想知道你在哪一步卡住，或者哪条记录整理错了。

## 中文短帖

在做 Travel Records：把邮箱里的酒店、航班和餐饮资料整理成可核对的清单，保留日期、金额、取消记录和来源。正在招募桌面内测用户，先试一段自己记得的行程。欢迎回复系统和使用场景，请勿公开发邮件或账单。介绍与合成样例：https://github.com/playsolo/travel-records-skill

## 内测反馈问题

在已安排的私密反馈渠道使用；公开渠道仅提供脱敏摘要。无需提交账号密码、授权令牌、完整邮件或原始账单。

1. 你使用什么系统、客户端和插件版本？首次设置是否成功？卡在哪一步，出现了什么脱敏错误？
2. 这次授权检查哪个账号及邮件日期范围？反馈中用“账号 A”等别名，不写邮箱。是否明确区分邮件年份和旅行日期？
3. 从首次设置到打开首份清单用了多久？还有哪些待处理项？
4. 你事先知道有几条目标记录，实际找回几条？是否提前告诉 Agent 目标酒店或订单线索？
5. 抽查了哪些日期、状态、金额和币种？有几项正确、几项错误或无法判断？
6. 哪个步骤最费力？下次整理旅行时，你是否还会使用，为什么？

## English community post

**Can you remember every hotel you stayed at last year? I'm building a tool to organize travel records from email.**

Confirmations, amendments, cancellations and final bills are scattered across an inbox. Travel Records organizes hotels, flights and dining reservations into a reviewable list of dates, status, amounts and sources. It distinguishes bookings from completed travel and keeps conflicts visible.

I'm inviting 10–20 frequent travelers to a private desktop beta. Start with a trip you remember: can you install it, open a useful list and spot missing or incorrect records? You do not need FotoNest for the review.

[View the project and current requirements](https://github.com/playsolo/travel-records-skill). Synthetic examples are included, so you can inspect the output before connecting an inbox.

If interested, reply to this post with your operating system, desktop client and the records you want to organize. I'll first check compatibility and the private installation route. Do not post email addresses, screenshots, bills or booking numbers. Mailbox access requires your own authorization.

Real-mail validation is limited and mainly covers hotels; flights and dining need more examples. Web, mobile and unattended continuation remain unverified. Feedback about setup failures and incorrect records is especially useful.

## English feedback questions

Use an arranged private feedback channel; public reports should be redacted. No passwords, tokens, complete emails or original bills are needed.

1. Which OS, desktop client and plugin version did you use? Did setup work? Where did it fail, with what redacted error?
2. Which account alias and mail-date range did you authorize? Were mail years distinguished from trip dates?
3. How long did it take from setup to opening the first list? What work remains?
4. How many independently known target records were found? Did you give the agent target hotel or order clues beforehand?
5. How many checked dates, statuses, amounts and currencies were correct, incorrect or uncertain?
6. Which step took the most effort? Would you use it for your next travel review, and why?
